Gaps and probable bugs

Found by reading the code, not by running it. Each is worth a ticket or a decision; none is fixed by these docs.

WhereWhat
frontend/src/App.tsxProbable bug: if the socket drops mid-turn, nothing clears the streaming state, so the composer stays locked until the page is reloaded.
backend/app/api/recent_raids.pyPOST /api/recent-raids/mplus/{code}/{fight}/investigate has no per-user investigate limit; the raid endpoint POST /api/raids/{code}/investigate has one (sc-352).
bin/00_init_migrate_db.shAny failed alembic upgrade head falls into the bootstrap path, which stops with an error when the BOOTSTRAP_ADMIN_EMAIL user already exists. backend/cli/init_db.py checks for an admin first and doesn't have this problem.
In-process stateAll five rate limiters, the kickoff pre-fetch cooldown (services/kickoff_prefetch.py), spawn de-duplication (services/background.py), raw-store tombstones and indexer stats live in memory, although Redis exists. This blocks running more than one uvicorn worker; the backend image runs a single process.
Browser telemetry (observability/alloy/config.alloy, backend/app/telemetry/setup.py)Three known gaps, all deferred to the backlog. The Faro receiver shares the memory limiter and export queues with every other signal, and its rate limit is global, so a flood from the browser port can slow the backend's and the build layer's telemetry; a chunked body without Content-Length is not capped by the size limit in Alloy 1.21.3. REST calls take the browser's traceparent and baggage through FastAPI's own instrumentation without the checks the chat socket applies. A client can choose the trace id its chat turn joins.
Readiness gate (PERF-001, sc-156)The models boot step is required, so the readiness gate stays shut until live model discovery finishes.
backend/app/kb/embedder.py, wcl_agent/llm/generation.pyEmbeddings always use the Google genai client, also under WCL_LLM_PROVIDER=anthropic. Decision D2 in sprints/2026-10-31/decisions.md says anthropic covers every model call and Google credentials aren't needed.
build_agentNo web search on Claude chat turns, on either provider (web_search = not _is_anthropic(model)). Guide research does search on Claude.
WCL_ANTHROPIC_CLASSESThe default haiku:1,sonnet:1,opus:1 gives each Claude class one model, so the same-class fallback never has a sibling for Claude, including every turn under anthropic.
Raw store → RedisA store hit for a report confirmed public still back-fills shared Redis. A report later made private can stay reachable by its code for up to the re-verify window (1 day) plus the Redis TTL (24 h). Grant-only hits no longer back-fill (sc-296). Closing it fully needs workspace-aware keys or no back-fill from the store (specs/039-local-first-data/research.md R9).
TombstonesDeleted or private report codes are remembered per process (_Tombstones in services/fetch_persistence.py, 10 min, 1024 codes) and lost on restart; Redis holds a wcl:v1:gone:<code> marker.
Knowledge baseWCL chunks show up in search only while their fetch passes the visibility check within RAW_STORE_REVERIFY_DAYS (1 day). The backfill can't chunk plain damage, healing or cast tables, because stored rows keep no query text. kb_chunks.region and realm are never filled; search has no zone, guild or kill filter; the retrieval metrics are process-wide, with no per-workspace view (Observability).
Cost and usageNo accounting of model cost in the app: nothing is stored per user or conversation. Token counts are telemetry (GenAI spans and metrics, when an OTLP endpoint is set) and the turn stats log line. Mimir turns them into an estimated list-price cost from a generated price table, shown on the dashboards; cached input is priced as input, so cache-heavy turns read high (Observability).
observability/alloy/redact.ottlThe NAME: value redaction rule matches any name containing session, key or auth, so harmless text is masked too (a Claude Code hook name such as SessionStart:… shows as SessionStart:<redacted>). It is the intended trade; nothing narrows it yet. Redaction of curl -u user:pw, --password <v> flags and literal .env values is also not built.
backend/migrations/versions/0021_*The migration imports wcl_agent.client.queries and the private _flight_key; renaming either breaks a fresh upgrade head.

Unused or half-wired

  • The Python plotly package is declared in pyproject.toml (justified in specs/005-guild-context-artifacts/plan.md), but nothing imports it: chart_spec_to_plotly in services/charts.py builds the dict by hand.
  • remark-gfm is declared in frontend/package.json but never imported; Streamdown brings GFM itself.
  • The tool_progress frame is declared in backend/app/schemas.py and wsClient.ts but never sent.
  • create_chart and get_coaching_brief have no label or spell, though frontend/src/lib/spells.ts says every tool must be mapped.
  • POST /api/conversations exists but the frontend never calls it; GET /api/admin/guide-reports and GET /api/admin/cache-stats have no screen.
  • backend/app/db/timestamps.py was meant to hold the shared UTC rule (sc-216), but only services/profile_proposals.py uses it; private copies remain in eight modules (guide, raw fetches, knowledge base, sessions, invitations, password reset, admin users).
  • users.email is String(320) in the model; only migration 0002 makes it citext.
  • backend/Dockerfile installs uv with an unpinned pip install uv; the dependencies themselves are locked by uv.lock.
