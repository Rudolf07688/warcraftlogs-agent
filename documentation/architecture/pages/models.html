Models & providers

Every model call in the app goes through one provider layer that knows which provider is active: Vertex AI (Gemini, plus Claude from Model Garden) or the Anthropic API (Claude only). The selectable chat models are discovered live at startup, and rate limits are absorbed by one shared retry loop that can move a busy chat turn to a second model of the same class. How the agent uses its model is on Agent runtime & tools.

Providers

Tech google-adk==2.10.0 google-genai 2.25.0 (via ADK) anthropic[vertex]>=1.11.0 (lock 1.11.0) google-auth (ADC)

What it does, and where it lives

  • One switch. WCL_LLM_PROVIDER is vertex (the default; unknown values fall back to it with a warning) or anthropic. wcl_agent/llm/provider.py reads it once per process, so a change needs a restart. It is the only module that reads the switch or ANTHROPIC_API_KEY and the only one that builds model clients (genai_client(), anthropic_client(), async_anthropic_client(), adk_client_kwargs()).
  • vertex: Gemini through ADK's Gemini class and google-genai, on Vertex AI with Google application default credentials when GOOGLE_GENAI_USE_VERTEXAI is true (otherwise a plain API-key client, the AI Studio setup, with no catalog). Claude through Model Garden with AnthropicVertex / AsyncAnthropicVertex.
  • anthropic: Claude through the Anthropic API (Anthropic / AsyncAnthropic) with ANTHROPIC_API_KEY, held as a pydantic SecretStr and passed straight into the client. Gemini is not served: a Gemini id set for a role is ignored with one warning and the provider default is used. A missing key is logged once at boot (credentials_error()), the greeting is not primed, and discovery serves the fallback list.
  • Where Vertex calls run. wcl_agent/llm/vertex.py → model_location() reads WCL_MODEL_LOCATION (default global). Every Vertex model client uses it, so GOOGLE_CLOUD_LOCATION can stay regional for everything else. vertex.py also owns the project id and the Model Garden catalog listing.
  • Model ids. Dated Claude ids are name@YYYYMMDD on Vertex and name-YYYYMMDD on the Anthropic API; to_provider_id() is the one place ids are rewritten. Any id containing claude is a Claude id (is_anthropic_model()). A chat whose stored model is not served (for example after a switch) continues on the default (resolve_chat_model() in backend/app/model_state.py).
  • Embeddings for the knowledge base (KB_EMBED_MODEL, default gemini-embedding-001, 768 dimensions) always run on the google-genai client, whichever provider serves chat. See Knowledge base.

Why

Config only, one line plus a restart: every model setting already needed a restart (runners are cached per model, discovery runs at startup), and the provider layer keeps a runtime toggle or both-providers-live mode cheap later. Alternatives: an admin-only runtime toggle; both providers live with each chat choosing.sprints/2026-10-31/decisions.md D1

One module owns the provider decision and every client, so call sites stay provider-free. Alternative: keep the builders in vertex.py (a module named "vertex" building Anthropic API clients misleads).specs/032-llm-provider-switch/research.md R4

Vertex with ADC: no API key in the repo, and the same code path works locally and on Cloud Run with an attached service account.specs/001-streaming-chat-frontend/research.md §9

Model calls at global: tested live on 2026-10-18, europe-west1 serves only Gemini 2.5 and no current Claude; global serves all of them.documentation/live_model_probe.md (Regions); wcl_agent/llm/vertex.py docstring

Where models are called

Tech ADK Runner wcl_agent/llm/generation.py

What it does, and where it lives

Two paths. Turns that need tools go through the ADK agent (stream_response() in backend/app/agent_runner.py). One-shot calls go through wcl_agent/llm/generation.py: generate_text, generate_json (schema-constrained output), generate_grounded (Google Search on Gemini, the server-side web search tool on Claude, web fetch on the Anthropic API only) and embed_texts. It picks the client by model family, builds each client once per process, and runs every call through the shared retry loop with the SDKs' own retries off. Each model request through the loop (a grounded Claude search can make several) runs inside one GenAI client span (chat {model}, or embeddings {model} for embed_texts) with the operation, provider name, request and response model, token counts and finish reasons, and error.type on failure. It carries metadata only, never the prompt or the reply, and does nothing when telemetry is off (see Observability).

Live model discovery

Tech Vertex REST v1beta1 publisher models Anthropic Models API redis>=6 (model_catalog family)

What it does, and where it lives

wcl_agent/llm/models.py → discover_models() runs once at backend startup, in a thread, as the "models" boot step (_load_models() in backend/app/main.py).

  • catalog mode (WCL_MODEL_DISCOVERY, the default). Under vertex it lists both Model Garden publishers (google, anthropic) concurrently from the REST v1beta1 catalog; under anthropic it lists the Anthropic Models API (an alias such as claude-sonnet-5-5 wins over a dated twin). It keeps GA and public-preview entries, sorts them into classes with anchored patterns (Gemini pro / flash / flash-lite, Claude haiku / sonnet / opus), probes the newest keep + 2 per class in one concurrent wave and keeps the newest keep that answer. Defaults: WCL_GEMINI_CLASSES=pro:2,flash:2,flash-lite:2 (empty under anthropic) and WCL_ANTHROPIC_CLASSES=haiku:1,sonnet:1,opus:1. A 429 that persists stops a class ("no quota"); not-enabled or failed probes move on to the next version.
  • The probe is a one-token call that carries one dummy function declaration, 10 s timeout, so a model that rejects tools is never offered.
  • Fallbacks. A listing that fails or has no models falls back to probing the static lists (WCL_GEMINI_MODELS, WCL_ANTHROPIC_MODELS); if nothing passes, the configured WCL_MODELS list is served with degraded=true, so the picker is never empty. Without Vertex (GOOGLE_GENAI_USE_VERTEXAI off) catalog mode drops to static. static mode probes only the configured lists.
  • Shared result. A real catalog result is cached for 6 h in the model_catalog cache family (Redis), keyed by provider, project, location and the class settings; only 10 minutes when a model was lost to a likely transient error; fallback and degraded results are not cached. A cached value holding ids of an unexpected shape is thrown away and rediscovered. The default always follows the current WCL_DEFAULT_MODEL: the configured id if served, else the newest Gemini flash, else the first model.
  • Serving. The set lives on app.state and is read only through backend/app/model_state.py (get_model_state, resolve_chat_model, fallback_model_for). GET /api/models (backend/app/api/models.py, signed-in users) returns {models, default, degraded, provider}; the picker shows the provider label (Frontend).

Why

The owner asked for it: "The available models must be dynamically fetched from the available gemini and anthropic models on vertex."specs/002-agent-enhancements/spec.md (Input, item 4)

A live catalog instead of a fixed .env list: every model release used to need an edit and a restart. Only the REST listing returns launchStage; the probe carries a function declaration because the chat agent always sends tools. Alternatives: genai models.list (no stage, Google only); regional catalogs (they differ); a plain "hello" probe (misses tool-incapable models).specs/016-live-model-discovery/research.md R1, R3

Caching the result in the shared cache lets restarts and other workers skip the listing and the probes.specs/016-live-model-discovery/research.md R6

The provider is part of the cache key, so one provider's catalog is never served under the other; an empty listing counts as a failure for Vertex too.specs/033-anthropic-discovery-label/spec.md (Clarifications Q4, Q5)

429 handling (feature 011)

Tech asyncio ContextVar current_turn

What it does, and where it lives

wcl_agent/llm/model_retry.py. RetryingGemini and RetryingClaude override ADK's generate_content_async and run one shared loop, generate_with_retry(); generation.py uses the same loop for one-shot calls. The SDKs' own retries are off (Gemini HttpRetryOptions(attempts=1), Anthropic max_retries=0).

  • What counts as "wait and retry" (is_rate_limited()): google-genai APIError with HTTP 429 or 503, or status RESOURCE_EXHAUSTED / UNAVAILABLE; Anthropic RateLimitError, OverloadedError, or any status 429, 503 or 529. Anything else is raised at once.
  • Schedule (RetryPolicy): 5 attempts, 2 s initial, ×2, at most 30 s per wait, up to 1 s jitter, 90 s total waiting per model request. A numeric Retry-After wins. A wait that would exceed the budget (or a deadline) ends the loop with ModelRateLimited.
  • Never after text. Nothing is retried once a response chunk has been yielded, because a mid-stream retry would duplicate text.
  • Visible. Each wait first pushes a model_retry record (attempt, max attempts, seconds) into the turn's queue, so the browser can show "retrying" while the producer sleeps.
  • Round cap. WCL_TURN_ROUND_CAP (6) limits lookup rounds per turn (Agent runtime). Runners are cached per model, so policy changes take effect after a restart.

Why

Own retry loop instead of SDK retries: a native retry is invisible to the app, so nothing could show "busy, retrying" or count retries, and the two SDKs back off on different schedules with no shared budget. Overriding ADK's single model-call seam gives one loop for both providers. Alternatives: native SDK retries only; ADK on_model_error_callback (cannot re-issue a request); re-running runner.run_async (duplicates the user message in the session).specs/011-agent-rate-limit-relief/research.md R1

Fallback to a same-class model (feature 021)

Tech time.monotonic in-process rate-limit memory

What it does, and where it lives

A chat turn may switch once to its sibling: sibling_model() in wcl_agent/llm/models.py picks the served models of the same publisher and class, newest first; the newest falls back to the second, any other to the newest. A class with one served model has no sibling, so with the default classes every Gemini class has one and Claude classes (one model each) do not. Only the chat socket passes a sibling (fallback_model_for()); generate_with_fallback() runs the rules per model request:

  • Short probe first. While the turn can still switch, its own model gets 2 attempts within 10 s, not the full schedule (sc-176).
  • Switch. Still rate-limited: one model_fallback record (from_model, to_model), then this request and every later one in the turn go to the sibling with the full policy. ADK's session already holds the turn so far, so nothing is re-run. For Gemini, the earlier parts of the turn get Google's documented skip_thought_signature_validator value so the sibling accepts them; only the request's copies change.
  • Memory. A model whose retries ran out in a chat turn is remembered for 5 minutes (RATE_LIMIT_MEMORY_S); the next turn on it switches on its first request.
  • Both busy. When the model and its sibling are both remembered as limited, the probe and the sibling's retries share one 10 s deadline on a monotonic clock that counts request time too (sc-268, sc-297), so the turn fails in about that long.
  • Web search follows. The web_search sub-agent's model is built with may_switch=False: it follows a switch the turn already made, never makes one, gets the same short probe, and a spent probe is remembered so the root's next request switches at once (sc-184).
  • What the player sees (backend/app/api/ws.py): "The model is rate-limited right now. Please try again in about a minute." when no switch happened, or "Both {class} models are rate-limited right now…" (for example "Both Gemini flash models") after one.
  1. If the turn already switched, the request goes to the sibling.
  2. If the turn's model ran out of retries in the last 5 minutes and the sibling did not, the turn switches now (one model_fallback frame).
  3. Otherwise the turn's model gets the short probe (2 tries within 10 s), or the full schedule when there is no sibling.
  4. Still limited, with a sibling and no switch yet: model_fallback, remember the model, retry on the sibling with the full schedule (inside the shared 10 s deadline when both were already known to be busy).
  5. No sibling: rate_limited "The model is rate-limited…". Sibling limited too: rate_limited "Both … models are rate-limited…".

Why

Fallback per model request, inside the wrapper: the ADK session already holds the turn's user message, tool calls and streamed text, so switching one request re-runs nothing and never duplicates text. Alternative: a turn-level re-run (duplicates the user message, needs session surgery, repeats tool calls).specs/021-ratelimit-fallback/research.md R1

Sibling by naming rules over the served set: no new state, and it works in static mode too. Alternatives: storing the catalog classes on app.state; a configured sibling map.specs/021-ratelimit-fallback/research.md R3

Gemini validates function-call thought signatures within a turn, and the parts before the switch were signed by the other version, hence the documented bypass value.specs/021-ratelimit-fallback/research.md R5

A separate typed model_fallback frame instead of reusing model_retry, whose attempt counters mean something else.specs/021-ratelimit-fallback/research.md R6

The both-busy budget is a deadline on a monotonic module clock, so request time counts and tests can drive a fake clock without patching time.specs/052-turn-and-startup-hardening/research.md (Deadline, sc-297)

Thinking and provider differences

Tech ADK BuiltInPlanner anthropic-beta: thinking-binding-controls-2026-08-01

What it does, and where it lives

  • Chat thinking. The agent's BuiltInPlanner asks for thoughts on every model; Claude gets thinking_budget=-1, which ADK maps to adaptive thinking. Thought parts never reach the user.
  • Stale thinking blocks. The app edits a turn's history on every request (stubbed tool results, the injected preamble, the instruction's timestamp), which invalidates replayed Claude thinking blocks. RetryingClaude._build_anthropic_kwargs() adds block_binding.prefix_mismatch_behavior = "drop_block" and the thinking-binding-controls-2026-08-01 beta header to adaptive-thinking requests, so the API drops those blocks instead of rejecting the request.
  • One-shot calls with thinking off (suggestions, titles): Gemini gets thinking_budget=0; Claude Haiku gets thinking disabled, Opus and Sonnet the lowest effort. temperature reaches Gemini only.
  • Round cap. Gemini also gets function calling NONE once the cap is reached; Claude relies on the wrap-up instruction.
  • Web search. The chat agent has web search only on Gemini; Claude chat turns are told no web search is available. Guide research searches on both: Google Search grounding (plus URL context) on Gemini, Anthropic's server-side web search on Claude, with web fetch for allowlisted domains only on the Anthropic API (Claude on Vertex gets the basic search tool and no fetch). A Claude research call that pauses is resumed up to 3 times, at most 10 searches and 5 fetches per call, and an organisation without web search enabled gets a clear error.

Why

Dropping stale blocks server-side keeps reasoning and avoids ordering and signature errors that client-side stripping causes. Alternatives: strip thinking blocks client-side; make history append-only (a redesign of trimming and the preamble).specs/032-llm-provider-switch/research.md R3

Claude needs an explicit budget, and ADK's Anthropic adapter rejected the old config, so every Claude turn failed until the planner passed -1.specs/032-llm-provider-switch/research.md R2

Usage logging

Tech Python logging

What it does, and where it lives

There is no cost accounting or per-user usage table. What exists is one turn stats INFO line per chat turn from stream_response() (backend/app/agent_runner.py): model, model requests, lookup rounds, retries, seconds waited, outcome, last and largest prompt tokens, cached tokens (from the response's usage metadata), trimmed tool results, tool calls and the fallback model. Discovery logs one line per class with the models it kept and why others were skipped. One-shot calls log only failures.

The turn stats line records prompt and cached tokens to measure the context trimming and the cacheable prefix.wcl_agent/llm/model_retry.py (TurnStats, PERF-004); specs/011-agent-rate-limit-relief/research.md R5
