Keeping these docs current

These pages describe the system as it is at the commit stamped on each page, not as a spec once planned it. They are re-checked against the code at the close of every sprint, so the stamp never falls more than one sprint behind main.

Close-out procedure

Run every command from the repo root of the checkout that holds the sprint tip (the sprint worktree during a sprint).

  1. See what moved. python3 .claude/team/archdocs.py changed reads each page's verified-at stamp, diffs the code from that commit to HEAD, and lists the changed files under the page that owns them. Tests, specs, sprint and meta files are ignored. Exit code 0 means nothing to re-check.
  2. Place unmapped paths. Files no page owns are listed as unmapped. Decide which page describes them (or whether a new page is needed), write it up, and add the path to PAGE_PATHS in archdocs.py so the next sprint finds it.
  3. Re-verify, don't append. For every listed page, read the diff and the code, then fix every sentence it touches: paths, names, env vars, defaults, limits, counts, versions, sequences. Count in the code; never copy a number from a spec. Remove what's gone. Describe the system as it now is, not the sprint's ticket history.
  4. Update the overview. When a layer gained or lost a component, a store or an external service, update the layer table, the cards and the system diagram on the overview.
  5. New page? Copy pages/_template.html, add it to PAGES in assets/nav.js and to PAGE_PATHS in archdocs.py.
  6. Stamp. python3 .claude/team/archdocs.py stamp writes the current commit and date into every page. Stamping a page says "every fact on it holds at this commit", so stamp only after step 3. A sprint that changed no mapped code goes straight to this step.
  7. Check. python3 .claude/team/archdocs.py check must be clean: every page in the nav, every local link and anchor resolves, tags balance, no duplicate ids, no <style> blocks, no external resources.
  8. Look at it. Screenshot each changed page at desktop and phone width and read the images: no horizontal scroll at 390 px, diagram labels inside their boxes and not overlapping. 
    google-chrome --headless=new --hide-scrollbars --window-size=1300,7000 \
  --screenshot=/tmp/<scratch>/page.png "file://$PWD/documentation/architecture/pages/<page>.html"
  9. Commit and report. Commit on the sprint branch (docs(architecture): …) and name the changed pages in the sprint review.

Done when archdocs.py changed exits 0 and archdocs.py check is clean on the sprint tip. That is the gate team-lead checks before the merge question.

The git hook

Git enforces the same gate. .githooks/pre-merge-commit runs archdocs.py gate on every merge commit into main, and .githooks/pre-commit repeats it when a stopped merge is finished with git commit. The gate compares each page's stamp with exactly what the merge commit will contain, and refuses while any page's code has moved past its stamp, a changed path has no page, or the site check fails. Merges into other branches and ordinary commits pass through.

  • Enable it once per clone: git config core.hooksPath .githooks (done in the main checkout on 2026-11-04; worktrees share the setting).
  • Fast-forward merges make no merge commit, so git runs no hook; sprint merges use git merge --no-ff.
  • Owner override for one merge: ARCHDOCS_SKIP=1 git merge …. The gate prints a warning, and the next close-out catches up.

Writing rules

  • Code wins. Where a spec, plan or ticket disagrees with the code, the page describes the code and says so in one line (and the drift goes on the open-points page).
  • Same shape per section: what it does and where it lives, the technology with its version range from the manifests, a diagram where a flow is hard to follow in words, then why.
  • Reasons are sourced. A green p.why bar carries a <cite> to a file that really says it (constitution, specs/NNN-*/research.md or plan.md, documentation/). Without a written source, use the amber Inferred badge.
  • Plain language. Short sentences, present tense. Tickets by a short plain name, the id in brackets at most (owner preference 23).
  • Self-contained. All styling in assets/arch.css, the nav and stamp display in assets/nav.js, inline SVG only, nothing fetched from the network. Pages work served over HTTP and opened as files.
  • Diagrams: svg.dg with <title> and <desc>, node classes node, node ext, node store, node core, animated arrows flow / flow ret, marker ids unique per page, and a numbered text version after every sequence diagram.
