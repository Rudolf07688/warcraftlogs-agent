    Decisions and deviations

    The decisions taken during specify, plan, implement and QA, in order.

    Specify · Q1
    Share public WCL data across tenants
    Supersedes feature 006 FR-019. No tenant or user id in wcl: keys; the per-tenant cache scope was removed.
    Specify · Q2
    Remove the in-process cache entirely
    Redis is the only WCL cache. Non-family queries go uncached; FR-026 keeps their cost visible.
    Plan · Q3
    Add a 7th family: world_zones
    current_patch() runs on every chat turn. Without this it would cost a WCL request per turn.
    Plan
    Map the doc's families onto the real tools
    Resolve name → id first (char_id); widen char_overview keys by zone/boss, metric and difficulty; report_player = per-player tables only.
    Implement
    TTL may be a function of the loaded value
    Token expiry, and finished vs live reports. No jitter on the token.
    Implement
    Admin stats keep working without INFO
    Families still show; redis: null when INFO is refused (as some managed Redis services do).
    QA · perf
    Batch again, memo hot values, count metrics in memory
    Lock default raised to 90 s (above the 75 s query timeout).

    Deviations from the task text

    • characters.py became normalize.py to avoid an import cycle with cache.
    • load_world_zones lives in menu.py; resolve_character in report_tools.py.
    • Stats path is /api/admin/cache-stats, not the doc's /internal/…, so it reuses admin auth.
    • drain_metrics only waits on the current loop's work. The cross-loop wait hung the test suite.
    • Rate-limit and identical concurrent queries now share one request (single-flight applies to all).

    Decision needed product

    ○PERF-008char_reports TTL (5 min) is shorter than the welcome-page refresh gap (15 min), so its hit rate will read "review". With batching, a miss costs no extra request. Options: accept, raise the TTL (staler welcome page), or lower its review threshold.

    Set aside on request security · bugs

    These findings were reported but deliberately not addressed in this round:

    • SEC-001 (High): compose publishes Redis on all interfaces with no password, and it holds the WCL token. Fix: 127.0.0.1:6379:6379.
    • BUG-001 / SPEC-002 (Medium): a malformed REDIS_URL raises instead of falling back.
    • BUG-002 (Medium): lock release has no owner check. The 90 s lock makes this less likely but doesn't remove it.
    • SPEC-003 (Medium): "check again" only refreshes character rankings.
    • SEC-002 / SEC-003: no production Redis auth or TLS; public SECRET_KEY default (carried over).
