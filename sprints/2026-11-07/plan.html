Goal and flow

Goal: after this sprint, a developer tests only its own building block, the PO merges all streams and runs one full suite at the tip, the QA sweep reads only the sprint's diff and fixes only broken criteria, security holes and data loss, and each agent sees only the board entries that concern it.

How a sprint will run afterwards

Brief with facts for written and run paths→Developer: targeted tests, receipt for its area→PO: check receipts, merge all→One full suite at the tip→QA sweep of the sprint diff→Live pass once

This sprint's order

Launch 4 in parallel→Merge as hand-offs land→One full suite at the tip→Live checks: stack helper, browser→QA sweep (diff only)→Docs and facts pass→Review

The agent-file changes only take effect after the merge to main, so their effect is measured on the next sprint.

Key decisions

  • Four streams, no scrum master. The steer's grouping gives disjoint files; all agent-file stories go to one developer so nobody shares developer.md or product-owner.md.
  • All tier S. Team tooling has no data model, tenant data or security core; Spec Kit specs would cost more than they give.
  • New-tools story split into the stack/browser/token part (3 pts, Ansel) and the trace-query/finding-in-diff part (2 pts, Nils), so both build in parallel. Total stays 20.
  • Interfaces fixed up front as board contracts (board addressing, check.py receipts by area, facts for run paths, tool names), so Vera documents them while they are built.
  • User-level QA files (the QA-sweep skill and QA agent prompts live outside git) are proposed as files on the sprint branch; team-lead applies them.
  • No security review at hand-off: nothing is security-core under the hand-off review rule. The end sweep reads the sprint diff.
  • Merge the new way already: check each stream's receipt, merge all, one full suite at the tip, bisect only on red.

Risks and what I'd drop first

  • A board filter hides a blocker or answer. The PO, SM and team-lead keep the full feed; developers always get entries addressed to them and replies on their keys; tested only in throwaway repos.
  • Agent files drift from the tools built in parallel. Contracts on the board; a change supersedes the key and Vera follows the latest.
  • Agent files grow instead of shrinking. Vera reports word counts per file; every new rule must cut the one it replaces.
  • Browser tool needs a new dependency. Allowed once (a dev dependency driving the system Chrome) after a board decision; prefer none.

Drop first: the offline token counter, then the finding-in-diff check.
