Headlines

  • The agent codebase is reorganised
    wcl_agent/ moved from one flat folder of 25 modules into six sub-packages (client, cache, tools, guides, llm, game). There's no behaviour change, and the test count matched before and after.
  • Chats are easier to find
    Conversations sit above Raids in the sidebar. Chats can be pinned, and new chats get a short generated name after their first reply.
  • The local data store has started
    Every successful Warcraft Logs response is now kept in the database. That lays the groundwork for answering questions without calling the API.
  • Fewer dead ends on rate limits
    When a model keeps returning 429s, the chat switches once to the other model in the same class and says so under the reply.
  • The welcome page shows Mythic+ runs
    The welcome page lists up to 6 recent raids and up to 6 recent M+ runs, and clicking a run opens a focused M+ review chat.

Fixed before shipping

  • Stored M+ runs disappeared for players without raids High
    While a refresh ran or after it failed, the welcome page hid the stored runs, and a failed M+ fetch failed the whole refresh. Now the runs always show, and an M+-only failure is logged without failing the raids.
  • Old chats could be auto-renamed after an upgrade Medium
    On a database where migrations don't run as a superuser, the step that protects existing chat names silently did nothing. It's fixed and verified on Postgres, including rollback on failure.
  • M+ runs listed the wrong characters Medium
    Each run named every one of your characters in the log. It now names only the ones who were in that key.
  • Documentation drift Low
    The README, developer guide and feature specs now describe what was actually built. Three small doc follow-ups remain as sc-193.

How it was verified

  • The full backend suite passes on main: 1064 passed, 3 skipped.
  • The frontend production build is green.
  • All three migrations went up, down and up again on a throwaway Postgres.
  • Each workspace sees only its own pins, titles and M+ runs (row-level security checked).
  • After a model switch, chat history records each turn exactly once, checked with the real agent framework.
  • A second review pass confirmed all four fixes.

Known limits accepted

  • Phone width: the page scrolls sideways because the sidebar never collapses. This predates the sprint, and the fix is filed as sc-175.
  • M+-only failure: there's no Retry button. It retries by itself at the next scheduled refresh, about 15 minutes later.
  • Fallback timing: the switch happens only after the normal retries, about 30 seconds (sc-176).
  • Switch notice: it's shown live but not saved, so it's gone after a reload.
  • Mid-stream 429s: they don't switch models, to avoid duplicating text.
