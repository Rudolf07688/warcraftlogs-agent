Branch sprint-2026-10-31c Base a5b84de Code tip 6dd57e7 Iteration Sprint 2026-10-31c (Shortcut 290) Not merged to main · not pushed

Barnaby now answers a repeat question about a finished raid from Postgres instead of calling Warcraft Logs again. That works in any chat, and Redis is still checked first. Stored data is shared only for public reports or for reports your workspace has fetched itself. A report that WCL says is private or deleted loses its stored copy. The store no longer rewrites unchanged payloads, and it writes in batches. In parallel, one tool call now starts one spell card, not 23. A turn fails fast when both models are rate-limited, model output can't load any image, and the chat scrolls back to your question when the answer finishes. The QA sweep found two High issues in the new store, both fixed in the one rework round.

How a report question flows now

Tool asks WCL for report data→Redis hit?→ no →Postgres store: every code public or granted to you, and fresh?→ no →Warcraft Logs→stored, grant recorded, Redis filled

Finished reports are kept for good, and live data is reused only within the 120 s live window. Any store error, or a store slower than 3 s, falls back to WCL. WCL_STORE_READS_ENABLED=false turns reads off and keeps writes on.

041 QA fixes (one round)

  • Gone detection: only our own REPORT_SUMMARY answered report: null can delete, and only when any error sits at the report path and reads not-found or permission. Subfield errors, aliases, padded codes and hand-written queries never delete.
  • Grants come from the response: a grant needs the report to come back non-null, from a summary query or a plain single-report query.
  • Writer: a batch that times out is retried item by item. Batches are capped at 20 items and 8 MB, and Redis eviction runs outside the timed part.
Known residual (sc-296): a store hit refills the shared Redis entry. A report made private can stay readable to anyone holding its code for up to the 1-day re-verify window plus the Redis TTL, about 48 h, against about 24 h before. A table-only flow notices that a report went private only at the re-check.

Risks

  • The WCL client's _fetch/query and _run_turn are hubs, and GitNexus rates the sprint CRITICAL (48 files). The changes are additive or narrow and covered by fake-stream and fallback tests. The kill switch can turn store reads off.
  • The summary query now asks for code and visibility, which hasn't been checked against live WCL. Live check 1 covers it.
  • The store adds 6–9 DB round trips to each Redis miss, and a hung DB costs 3 s per call (sc-295).
  • The revocation lag of about 48 h (sc-296).
  • The branch carries migration 0018. A merge to main needs alembic upgrade.

Went well

  • Self-review caught real issues before QA. Ansel's own bypass attempt found the alias and comment forgery class and the Redis lag, and he fixed or bounded both before hand-off.
  • Honest "not reproduced". Tomas didn't invent a fix for sc-213. The QA auditor later found the real cause in a path no one had looked at.
  • Reading the code before the ticket. Checking the code while writing briefs showed two planned stories had nothing to build. Swapping them out saved 3 pts of wasted work.
  • Bypass at hand-off and at merge, last sprint's lesson, was applied. My merge attempt passed the leads it couldn't settle to the sweep, and the sweep confirmed one (the gone-detection High).

Went badly, and the lesson

  • Both Highs were in the security core of 039, despite the design note and two bypass attempts. Both trusted the query text where they should have trusted the response. Lesson: for a security rule over external data, the brief should say "derive trust from what the server returned, never from what was asked".
  • The plan report was late. I launched the developers first and wrote plan.html about 40 minutes later. It's non-blocking, but the owner couldn't read it while the sprint was starting. Lesson: write the short plan before launch. It costs minutes.
  • sc-213's AC1 was set up to fail: "root cause named" for a bug the story itself had misdiagnosed. A reproduce-first story should allow "not reproduced, here's the evidence" as an outcome.
Net: 19/19 points, no owner questions, and both High findings fixed within the one rework round. The team's own checks caught three issues before QA, and QA caught two more in the same trust boundary.
