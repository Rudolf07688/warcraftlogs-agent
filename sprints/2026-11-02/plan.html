Decisions, order and risks

Decisions

  • Team-lead's candidate kept, with one addition from the code: the fights list is capped at 60k characters, so on a long night the last kill can fall off the end. board #3
  • Three independent streams with disjoint files; one shared file (raids page API) split by function. board #6–9
  • All tier M. The stored-data stream pairs a migration with security fixes, but the migration only adds a flag and indexes. board #4
  • Each hand-off gets a scoped security review before merge.
  • Left out: UI epics, worker server, log upload, sub-agents (product direction); knowledge-base speed tickets go together next sprint.

Risks and what goes first

  • Breaker and turn accounting are state machines; edge-case tests come first.
  • The own-summary backfill must not widen what a workspace can see; a two-tenant Postgres test guards it.
  • The kickoff slimming must not drop data the answer needs; the live pass checks the answer.
  • Drop first: difficulty map, then the set_config and retry-budget items, then the per-family counters.
