Decisions, order and risks

Key decisions

  • The QA bug where a CORS preflight returns 500 with telemetry on sc-461 joins the sprint. It is in the same file as this sprint's bootstrap work, and it would break the browser live pass.
  • The feedback-ratio panel is dropped from the runtime dashboards. The app has no feedback feature, and quality signals are reserved in the spec.
  • The dashboard overcount bug sc-471 stays in the backlog because no story touches the build dashboards. Its rule (window equals step) is in every brief, so no new panel repeats it.
  • Other deferred QA stays in the backlog: browser trace context on the REST path sc-459, the shared browser pipeline sc-458 and telemetry details sc-460.
  • There are three parallel streams. Shared files (compose, Alloy config, datasources, the telemetry setup) are split by section, and those sections are posted on the board.

Risks, and what drops first

  • SQL comments carrying the trace id make every statement unique, which can defeat asyncpg's statement cache. Ansel measures this and decides.
  • The new Postgres log path could carry query parameters into Loki. It must pass through redaction, and a test proves it.
  • The build-to-runtime attribution (commit to seat to build cost) is an estimate. The dashboard states its rule.
  • 1Drop Pyroscope span profiles first.
  • 2Then the local alerts.
  • 3Then the infra dashboards (D9 to D11).
