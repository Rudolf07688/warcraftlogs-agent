Key decisions

  • 123 points, not 27: inline coaching briefs (sc-515) and background guides for the chosen spec (sc-168) wait. The first needs a live A/B measure of two turns; the second is the next onboarding slice.
  • 2The "Raids page" is new: today raids are a collapsible list in the sidebar. The page lives inside the app shell, one tab per raid, so the analyze button reuses the existing chat flow.
  • 3The raid-data story is split into an endpoint (Nils) and its screen (Tomas), joined by an agreed response format, so both build at once.
  • 4Portraits get their own endpoint instead of riding on the profile responses: the profile page must not wait on Battle.net, and onboarding changes those responses this sprint. The raids page portrait is a follow-up.
  • 5Shared files have one owner each this sprint (onboarding owns the profile schema, client and types); a prep commit lets the other streams keep their calls in their own modules.
  • 6One migration (0023), onboarding only. Portraits cache in Redis.

Risks and what goes first

Battle.net credentials: no developer calls Blizzard; team-lead runs any real check. If the keys are missing in the owner's stack, portraits fall back to initials and the live check is deferred.

Chat loop change (076): serializing turns can make a turn wait behind a stuck one. The brief makes liveness and cross-workspace safety tests mandatory, and the security review checks both.

Stored data gaps (072): older raids may lack participants or rankings in the store; the page shows what exists and offers the analysis chat for the rest.

Drop first if time runs short: schema notes (sc-514), then portraits on the welcome page, then the analyze button's styling.
