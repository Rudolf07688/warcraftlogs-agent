Epic 248 · Switchable LLM provider: Vertex AI ⇄ Anthropic API

Architecture in one picture

Chat agentGreetingSuggestions & titlesPDF reportsClass guides→ wcl_agent/llm/generation.py→ wcl_agent/llm/provider.py→ Vertex AI (Gemini / Claude)orAnthropic API (Claude)

Provider switch + Anthropic client for chat

  • WCL_LLM_PROVIDER selects the provider; the key is a secret, never logged or returned (tested with a fake key).
  • Per-role defaults under anthropic: chat, reports, guide author → Sonnet 5.5; guide review → Opus 5.5; suggestions, titles, greeting → Haiku 5.5. New WCL_GREETING_MODEL.

Process and retrospective

What went well

  • One owner plan review, then the team ran without further owner gates.
  • 032 published its provider contract early, so 035 specified in parallel and needed no changes after the merge.
  • Developers proved bugs before fixing them: the ADK dict root cause (sc-241), a race test that fails on the old code (sc-242), and the pre-existing Claude chat break.
  • File ownership kept both tracks conflict-free at every merge.

What didn't

  • Too much ceremony for the complexity. Per-feature spec/clarify/plan/tasks gates and relays slowed a straightforward change; the owner called it out.
  • Frequent crossed messages caused ACK loops and duplicate spawn requests.
  • 035 merged without a suite run on its rebased branch; one check went red until a follow-up commit.
Change for next time: single-pass mode for simple tasks
  • One developer runs spec → plan → tasks → implement straight through.
  • The scrum master only manages tickets (states, iteration, links): no gates, no relays.
  • One /qa-sweep at the end; fix only critical findings, defer the rest as qa-deferred.
  • Always run the full suite on a rebased branch before merging.
