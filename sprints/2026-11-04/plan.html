Goal: see the agent team and one chat request end to end in Grafana, keep telemetry across restarts, and mask secrets everywhere, with content captured in dev only.

What you will be able to do

Build layer (the agent team):

bin/claude-otel→Alloy (always on, disk queue, redaction)→Loki · Tempo · Mimir→Grafana

Runtime layer (the app):

Chat turn→invoke_agent→model call / tool→WCL request · SQL · Redis→one trace in Tempo

Order: both streams start at once. The stack stream does the stack first, then redaction, the wrapper and the Grafana links. The backend stream does the bootstrap first, then the content policy and logs, then the chat-turn trace and the one-shot model spans.

Live checks (a real Claude Code session with subagents, real model calls, the full stack with the app) are batched by team-lead on the merged tip.

Decisions and risks

  • Content capture defaults to off unless the app is explicitly told it runs in dev; compose says dev. ADK captures content by default, so only an explicit dev is safe.
  • Two tier-M streams with disjoint files; the compose file belongs to the stack stream alone, and the stack stream wires the backend's telemetry env from an agreed contract.
  • The backend stream is security-core: an independent security review at hand-off; its Highs and Mediums are the one rework round.
  • Chat turns run over a websocket, so the backend stream may wrap each turn in its own root span (one hunk in the websocket handler), granted on the board.

Risks: Alloy's disk queue is a public-preview component (pinned image, persistence test); ADK pins OpenTelemetry versions; global instrumentors could touch the test suite; Python 3.14 wheel gaps; RAM with the stack up. Drop order if it slips: datasource correlations, then one-shot model spans.
