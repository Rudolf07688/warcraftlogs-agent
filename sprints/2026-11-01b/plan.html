Sprint 2026-11-01b: big-report turns that finish, and clean-up

Branch sprint-2026-11-01b Base dd0c2df (main) Iteration Sprint 2026-11-01b (Shortcut 338) PO Maren · devs Nils, Ansel · no scrum master

Questions about large reports should end with an answer, cheaply: no 60,000-character table previews, no fetching every player one by one, no turn that ends on the interim line. Alongside that, the debt the last sprint's QA left in the knowledge base and local store gets paid down, and the test suite stops reading the real .env. Owner's line for the sprint: "Evolution is key."

User flow after this sprint

"Top 3 damage dealers on the last kill?"→one table call returns a compact top-N list→answer, no per-player fetches
Model returns nothing after its tools→a clear "no answer, try a narrower question" message, logged as its own outcome
Click a recent raid→ background →server warms the report's fights and boss tables→the agent follows a fixed playbook, mostly local hits→overview; tool calls per turn logged

Under the hood: knowledge-search hits are fenced off as data so a report title can't steer the agent; a private report can't come back after a race; one slow read no longer sends every workspace to Warcraft Logs; the local-answer rate stops overcounting; two messages written to one chat at once both save.

Order and dependencies

The streams are independent, so they run in parallel. Two shared files are split up front: the stored-data tools file belongs to Ansel except the one stored-table line Nils changes to the compact projection; the chat socket (ws.py) is Ansel's, so Nils solves the empty answer inside the agent runner. The .env fix goes first because every later "green" depends on a hermetic suite.

Key decisions

Tier M, no scrum master

Two streams with disjoint files, clear goals and no shared design question. One Spec Kit pass each; I merge.

Kickoff pre-fetch warms the cache

The server warms the shared cache and store when a raid is clicked, and the agent's own calls become local hits. It doesn't inject Warcraft Logs text into the turn, so no untrusted text gets a new path into the prompt and the chat socket stays untouched.

Split of the playbook story

Only the kickoff slice (sc-339, 3 pts) is in. Mythic+, benchmark and class-guide playbooks stay on the playbook story (sc-163, re-estimated 3) in the Backlog. New epic "Big-report turns that finish and cost less" holds all four.

Security review at each hand-off

Both features are security-core. A scoped qa-security review, prompted from the diff and the spec (not the developer's notes), runs before each merge; Highs and Mediums are the one rework round.

Risks, and what goes first if we run late

Risks

  • The 40k-token target can only be confirmed live; CI guards the table payload size instead.
  • The pre-fetch runs outside any turn and user: it must not widen visibility or burn the shared request budget.
  • Changing how the test environment loads settings can hide a missing variable that the app needs; the app path is checked separately.
  • The tombstone stays per process: fine for today's single worker, written down in the spec as such.

Drop order

  1. Recent-raid kickoff pre-fetch + playbook (sc-339).
  2. Chat message numbering race (sc-255).

Security stories are never dropped.
