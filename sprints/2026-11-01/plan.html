Sprint 2026-11-01: semantic knowledge base

Branch sprint-2026-11-01 Base ec966c5 (main) Iteration WCL App Q4 2026 (Shortcut 161) PO Maren · SM (new seat) · devs Ansel, Tomas, new dev-3

The agent searches what the app already knows (stored Warcraft Logs fetches, the grounded class guides and the workspace's past chats) before it calls Warcraft Logs. It can run several searches at once, and every result is one the asking user is allowed to see. This is the next step toward the epic 103 goal: answer 80% of questions without an external API call.

User flow after this sprint

Ask about a report→fetch stored (039)→ background →fights and tables chunked as text, embedded (Vertex, 768-d)
Each saved chat exchange→ background →chunk in the workspace's own table
Later, a related question→search_knowledge: 1–5 queries + typed filters, in parallel→vector + full-text, fused by RRF, visible-only→answer, often without a WCL call

Visibility never changes: WCL chunks follow the 039 sharing rule (public, or granted to the workspace, within the re-verify window); guides are global; chat chunks are workspace-scoped under tenant RLS, exactly like conversations today. Deleting a chat, a stored fetch or a guide deletes its chunks. Embedding never runs inside a chat turn.

Key decisions

Three chains, one developer each

Dependent work stays with one developer (lead lesson). sc-131 goes with the raw-store QA work, because sc-295 rewrites the read path sc-131 sits on, and sc-132 shares its counters with PERF-007.

Resolver and schema merge first

Every stream needs one of them. Merging them early lets the others rebase instead of stubbing.

P7 trial on four stories

sc-111, sc-112, sc-305 and sc-114 get a scoped qa-security review at hand-off plus bypass attempts (invisible fetch, foreign chat, widening filters, deleted chat). Findings and cost go on the board so the team can judge P7.

No scope added

Exactly the owner's 11 stories and 33 points. Ideas that come up go to the backlog.

Risks, and what goes first if we run late

Risks

  • Critical path sc-111 → sc-112 → real chunks for the eval. Mitigated: search and eval test on directly inserted chunks.
  • The image swap touches the owner's data volume: proved on a copy first; team-lead backs up the database before the switch.
  • Search results flooding the model's context (compare sc-302): hard output cap.
  • Disk at 21 GB free: throwaway pgvector containers are removed after use.

Drop order

  1. sc-115 live-mode measures (keep the prompt and the CI recall eval).
  2. sc-296 (an accepted risk today; the window is tunable).
  3. sc-113 backfill (new data still embeds).

Security-core stories are never dropped.
