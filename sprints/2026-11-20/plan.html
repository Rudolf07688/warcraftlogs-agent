Sprint 2026-11-20: fixes from your 7 November chat

Everything that went wrong in your live chat on 7 November, fixed in one sprint: event lookups that return data, Claude turns that are faster and always answer, a visible "thinking" line instead of silent gaps, and a coach that explains boss mechanics, keeps its tool housekeeping out of the answer and takes sensible defaults instead of asking.

Goal and user flow

A raider asks a big question about a night's kills. Today the turn goes quiet for up to a minute between tool rounds, may end with "I couldn't put an answer together", opens its answer with paragraphs about server errors and source ids, gets windowed event lookups back empty, and can't say what a boss ability asks of the player. After this sprint:

Question→Tools run (event windows and paging work)→"Thinking" line shows what the model is doing→Mechanic guide looked up when asked→Answer starts at the verdict, always arrives

Speed and stability

Claude calls reuse the cached prompt instead of re-reading 60–69k tokens each time; the final call keeps room for the answer after thinking, and retries once without thinking if it still runs out.

Coach quality

Boss-mechanic guides for the current raid tier with source and patch; one plain line when a tool fails; a sensible default with a one-line assumption instead of a list of questions.

Dependencies

  • The Gravebound figures depend on the event fix: same developer, in order.
  • Caching and the output budget share one Claude request builder: same developer.
  • The status line needs Claude's thought text, which the caching stream's request provides: a written contract between Vera and Edda.
  • The prompt routes mechanic questions to the new guide tool: a written contract between Ansel and Nils.

Risks

  • Mechanic guide content: the current tier's encounters aren't in the code, so Ansel sources them through a live check and public guides first. Bosses without good sources become a backlog ticket, never invented text.
  • Caching vs the minute-by-minute time line in the system prompt: named in Vera's brief, to solve inside her file.
  • Prompt size cap: five streams add text; the remaining room (about 1,150 tokens) is split per stream up front.
  • Interim text is only known as interim after the model calls a tool: the live view, the saved answer and the reload must agree.

Drop first: the defaults stream (sc-575) and the generic "Thinking…" fallback; then the Gravebound figures ticket if it closes with the event fix.

Key decisions

Decision and reason
Five parallel streams, no scrum master. Every file has one owner; there is no migration, so nothing needs sequencing.
Tool troubleshooting (sc-572) split by file owner. The saved-answer change lives in the chat runtime (Edda); the "say it once, plainly" rule lives in the prompt (Nils). The story moves to Under Review when both are merged.
Mechanic guides as curated notes plus a lookup tool, not database rows. The knowledge-base-first route at the lowest cost: a few dozen entries need no vector search or migration and work on Gemini and Claude alike. Web search stays its own ticket (sc-380).
Caching and output budget with one developer. Both change the same Claude request builder; the thinking retry must not fight the cache layout.
Prompt budget split up front. Guides +400, prompt +250, tool docs +100, status line +50 tokens of about 1,150 left; the cap is never raised.
Answer-quality checks pinned to stored facts. The live pass checks tool results and stored values (a guide was found, Traecie is a Mage), not the model's wording.
