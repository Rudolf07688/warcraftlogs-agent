# Quickstart: Verifying the Profile & Class-Guide Pages

Manual verification of the three slices. Assumes the app runs locally (FastAPI backend +
React frontend), an activated account, and (for guide generation) working Vertex/WCL creds.
Run migrations first: `uv run python -m backend.cli.init_db` (or `uv run alembic -c backend/alembic.ini upgrade head`) — this applies `0007_spec_guides` (creates the global table, migrates existing per-character guides, drops the retired columns).

## Prereqs
- `uv sync` + backend running; frontend (Vite) running; signed in as a tenant user (a second account available to prove the guide library is shared but user data isn't).

---

## US1 — Dedicated, themed Profile page (P1)

1. From the chat view, open the profile → ✅ you land on a **dedicated page** at `/profile` (not a modal), with a Warcraft-themed look and a **tab bar** (Characters / Class Guides).
2. On **Characters**: set self, add ≥3 friends, change a friend's raid role, clear one back to inferred, set a main guild → all persist as before; re-add an existing friend → friendly **"already added"**.
3. Switch to **Class Guides** and back → the Characters tab keeps your in-progress input (no reset).
4. Controls (buttons/inputs/selects/cards) look consistent and themed; keyboard navigation works.

Pass = US1 scenarios; SC-001, SC-007.

---

## US2 — Class Guides tab + shared spec-guide library (P1)

1. Open **Class Guides** → ✅ **every** class and spec is listed, each with one status: Downloaded / Generating / Failed / Not downloaded.
2. Pick a spec with **no character** and click **Generate** → status goes to *Generating…* then *Downloaded*; click **View** → the guide renders.
3. Force a failure (e.g. temporarily bad guide model id) → status becomes **Failed**; click **Retry** → it attempts again and reaches a terminal state (never stuck).
4. Click **Refresh** on a Downloaded guide → it regenerates and replaces the content.
5. **Shared**: sign in as the second account → the guides generated by the first account already show as Downloaded (library is global). Confirm no first-account characters/friends/guild leak into the second account.
6. **Rate limit**: click Generate rapidly across many specs → after the cap you get a clear "slow down" message, not cascading errors.

Pass = US2 scenarios; SC-002, SC-003, SC-005, SC-006.

---

## US3 — Auto-fetch reconciled with the shared library (P2)

1. Add a friend whose spec **already has** a Downloaded guide → ✅ the character shows the guide immediately and **no new generation** runs (watch the Class Guides status / logs).
2. Add a friend of a spec with **no** guide → generation is triggered into the shared library automatically (best-effort, non-blocking).
3. Ask the assistant a question about a character whose spec guide is ready → the guide is present in its standing context (as before).
4. Remove a character whose spec guide others rely on → the **shared guide remains**.
5. A character with an unresolved spec → no guide attached, character fully usable; preamble unchanged.

Pass = US3 scenarios; SC-004.

---

## Migration / no-regression

- After `0007`, previously-`ready` character guides appear in the Class Guides tab as Downloaded for their `(class, spec)` (no loss, FR-018).
- With an empty guide library and unset roles, the agent context is byte-identical to before (no regression).
