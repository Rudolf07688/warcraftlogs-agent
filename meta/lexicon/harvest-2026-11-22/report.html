Findings

1. The team already grows its own language, and drops it again

During the scrum-master sprints (10-25, 10-26, 10-31c) the team invented a short message protocol on its own: ACK (487 uses), GO implement 029, 030 MERGED, rebase, GRANTED. It disappeared entirely once the scrum master became optional. Other terms appeared when a tool introduced them: RESULT/RECEIPT came with check.py on 11-01b and stayed. hand-off and fix round are stable across all 16 sprints. So a culture already exists. It just has no memory: a term lives only as long as the role or tool that carries it. See the second tab.

2. The biggest repeat is place names, not phrases

Full paths make up the largest verbatim repeats: /home/rudolf/dev/wcl-worktrees/sprint (673 times), …/wcl-worktrees/dev-* (631), the main checkout (212). Each costs 20–29 tokens, because paths tokenize at about 1.7 characters per token against about 3.3 for prose. /home/rudolf/dev/wcl-worktrees/sprint/sprints/ is 27 tokens, and @sprint/ would be 4. That's roughly 33k tokens written over the 16 sprints, 1,069 of those times in briefs, which every developer re-reads on every call.

3. The same status is written a hundred ways

The tightest paraphrase groups are status reports with different numbers in them:

  • Test results (6 groups, about 270 units): "The test suite passes: 1060 passed, 3 skipped, 1 deselected." / "Suites: SQLite 1744/64 skipped, full Postgres 1808." / "On the merged branch the backend suite passes (1171 tests)…"
  • Severity counts (2 groups, 55): "Totals: 0 Critical, 2 High, 5 Medium, 19 Low." / "It found 14 problems, none critical: 1 high, 4 medium and 9 low."
  • Merges, resets, board states: "The product owner accepted 025, and I merged it into the sprint branch (041ef2a)" (21); "The dev-b worktree is reset to the sprint tip" (38); "All ten sprint stories are now Under Review" (25).

These are ideal for a message grammar: one fixed line per kind, like TESTS pg 1796/0s @f1835c4 or SEV 0C 2H 5M 19L. That's shorter, it can't be misread, and a tool can parse it. That last part is what the planned heatmap needs.

4. Briefs repeat the same rules word for word

"Follow your report format exactly; reply with path, counts, top 3." (74 times). "Return your hand-off as your final result." (52). "First action: python3 .claude/team/member.py me --seat dev-N" (49). "Use a clean env: env -i HOME=$HOME PATH=$PATH uv run --extra test pytest -q" (29, 30 tokens each). "Do NOT read from or write to the owner's checkout" (15). The trailer line on commit messages (29). Each of these is a rule that belongs once in the agent definition, with the brief using a short name for it, or nothing at all.

A candid note on the cost case. All the agent-to-agent text here is about 1.4 M tokens across 16 sprints. The repeats above add up to perhaps 5–10% of it. Most of the team's spend is context re-read on every call: 192 M cache-read tokens in the 11-22 sprint alone. So the lexicon saves something directly, and much more in briefs that get re-read. But its stronger case is precision (one meaning per term) and structure (lines a tool can count). The largest token lever, standing prompts in agent definitions, wasn't in this harvest's sources. That would be step 2.

Measured, not assumed: invented abbreviations are a bad deal. "QA sec rvw @ HO" is 11 tokens; "D18 review" is 4; the full sentence D18 stands for is 40. So the lexicon should name concepts (IDs, short words) and never abbreviate letters.

C. Concept terms

Already alive (write down as they are): hand-off, receipt, fix round, sprint tip, live-check, D18, security-core, qa-deferred, wrap-up, close-out, scope:NNN.

New names for repeated rules: main-ro (never read, write or switch in @main), seat-start (run member.py me first, then your agent definition), qa-reply (report format exactly; reply with path, counts, top 3), clean-env (the env -i pytest line, unless check.py replaced it).

Method

  • Sources: meta/sprints/*/board.jsonl (1,295), sprint briefs (103 files), member memories, and the agent transcripts still on disk: agent text (2,214), Agent prompts and SendMessage bodies (1,247), Shortcut comments (482). Chat written for the owner was left out.
  • Units: sentences of 5–70 words, with code fences, tables and headings removed.
  • Embeddings: Vertex gemini-embedding-001, 768 dimensions, task CLUSTERING, cached under ~/.cache/wcl-team/. The vectors are in a team pgvector container (pg.py up lexicon, table lex_unit), never the app database.
  • Groups: leader clustering at cosine ≥ 0.93. A first pass at 0.88 grouped by topic, not by meaning (gemini-embedding's baseline similarity is high).
  • Tokens: measured with count_tokens on samples: prose about 3.3 characters per token, paths about 1.7.
  • Data: candidates.json next to this report: 432 coined-term candidates, 300 phrases, 300 groups.
