P7, the scoped security review: verdict

  • Cheap and useful. Four runs cost 1.61 M units (4%), about 80–110k tokens and 5–7 minutes each. They found 2 Mediums and about 12 Lows, all fixed or ticketed before the final sweep. No pass found a way around the visibility rules.
  • Who writes the prompt matters. Nils's own review of 044 found and fixed the pool-exhaustion Medium. Ilse's independent pass, prompted from the code and not his notes, found the two most useful issues. One was the eval seeding fake public reports into the app's real database, which I would have run in the live pass.
  • The scope missed one. The final sweep's only cross-workspace leak (a cache single-flight sharing a grant-only store hit) was in 045, which wasn't on the P7 list. Maren's proposal: any change to a shared cache, single-flight or Redis key path counts as security-core.
  • Recommendation: keep P7. The scrum master (or, in tiers M and S, the product owner) launches it from the code, one run per security-core hand-off, with the wider scope above.

Live pass (team-lead)

Run on b7a3eda and 268e22c. The database was backed up first (.git/db-backups/pre-pgvector-20261101-1229.dump), moved to pgvector/pgvector:pg17-trixie and migrated to 0019. All 42 conversations survived with no collation warning; pgvector is 0.8.7 and RLS is forced on the chat chunks.

  • 043: Vertex accepts 8 texts per request. The backfill dry run estimated about USD 0.01; the confirmed run took 83 s and embedded 440 chunks, all unit-length at 768 dimensions; a rerun adds 0. While credentials had expired, chunks were kept for keyword search and retried at the sweep.
  • 044: hybrid guide search answers with section-level sources. A fact said in one chat is found from another; deleting that chat removes its chunks. The eval on a throwaway kbeval database gives recall@8 hybrid 1.0, vector 1.0, keyword 0.983, and the eval refuses the app database.
  • 045: list_stored_fights answers from the store in 24 ms with no WCL call; cache stats show the store counters and the local-answer rate.
  • New bug sc-334, which predates this sprint: a top-3 damage question on a large report sends up to 397k prompt tokens in one request, because the 60k-character table preview makes the agent fetch each player separately.
  • I fixed one test myself: test_record_refuses_without_an_embedder asserted embeddings.json is absent, which broke once the recorded set was committed. Separately, the suite reads a .env in the working directory, so a symlinked live .env turns 22 tests red; run suites without it.
  • Not testable live: the database-pause breaker (login needs the database), the Redis key for unlisted reports (there are none), and a second workspace. Tests cover all three.

What worked

  • Tier L sized right. Three developers on three dependency chains, each chain kept with one developer (my lesson from 10-31). Milestone merges early (resolver, store, and 045's part 1) unblocked the others within the first hour.
  • Developers deciding and posting. Ansel swapped the image to pg17-trixie after proving a collation mismatch on a copy of the volume; Tomas redesigned his tombstone when an unchanged 039 test contradicted it. Both were posted with reasons and accepted without a round trip.
  • Gates in one round. All six spec and plan gates passed with no rework; Ilse folded small changes into the next step.
  • Mutation checks are now routine. Every developer broke their own guards to prove the tests bite.

What to change next time

  • Wake-ups are needed. An idle agent sees no board entries until a message wakes it. I first told Ilse I'd stop forwarding, then had to take it back. Rule for the team-launch skill: one-line wake-ups per hand-off to the idle merger, never full forwards.
  • "Green" must be shown, not said. Tomas's QA fix test failed in every clean run, and he read his own output wrong. Maren's proposal: the hand-off pastes the tail of the env -i run (command plus pass line).
  • Mutation leftovers. Nils committed a mutated tenant check once (caught by his next run, never merged): restore from a cp backup, not git checkout, and never chain pytest | tail && git commit.
  • Spec Kit's feature.json trap overwrote another feature's plan once (restored, not committed).
  • Live credentials: check gcloud auth application-default print-access-token before the live pass, and recreate the backend after a login, because the bind mount keeps the old file.
