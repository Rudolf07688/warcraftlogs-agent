Why 1.63 and not about 1.1. Three causes, measured from the table above:

  • The fix round was four times last sprint's (3.74 against 0.90). QA's six findings over the bar (the cut-off with text, the Gemini re-run after an answer, the cache missing in long chats, drop rechecks, retry notices, the Raids rankings key) plus both live findings were real defects in code that every model call goes through. Without the fix round the sprint is 24.0 M, or 1.41 M/pt.
  • Fixed costs, few points. The PO (6.96) and I (2.74) cost about the same as on 11-20 (6.36 and 2.74), spread over 17 points instead of 22.
  • The tickets were under-pointed. They were QA follow-ups pointed for the fix, not for the hardening the fix needed. 085 at 1.03/pt carried a D18 rework, the same pattern as 080 last sprint (0.81).

By stream type the numbers sit where earlier sprints put them: data and backend about 0.3/pt, the LLM path 0.45–0.62, and full-stack work with a security core about 1/pt. Docs close-out fell from 1.92 to 1.16, because the PO passed Tomas the list of already re-stamped facts.
